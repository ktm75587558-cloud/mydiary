# 작업 인계 노트

마지막 갱신: 2026-10-04

## 지금 무엇인가

**다이어리 앱 '고슴도치'.** 혼자 쓰는 일기장이고, 달력에서 날짜를 고르면 그날의 기분·할 일·기록을 적는다. 서버도 로그인도 없고 데이터는 이 브라우저에만 있다.

`index.html`을 **더블클릭해서 바로 연다.** 서버가 필요 없다.

## 이번에 한 일 — 할 일 앱에서 다이어리로 재설계

### 왜 갈아엎었나
1주차 학습용 할 일 앱에 날짜별 메모 칸이 붙어 있던 상태였는데, "매일 쓰는 다이어리"로 쓰려니 중심축이 안 맞았다. 인터뷰로 정한 전제는 이렇다.

| 항목 | 결정 |
|---|---|
| 사용자 | 나 혼자 |
| 중심축 | 날짜가 중심, 할 일은 그날 안의 요소 |
| 저장 | 이 기기에만 (`localStorage`) |
| 환경 | 데스크톱 중심 |
| 화면 | 월간 달력 + 선택한 날 상세 (2단) |
| 할 일 | 그날에 속함, 자동 이월 없음 |
| 실행 | `file://` 더블클릭 유지 |
| 기존 데이터 | 버림 |

### 파일을 나눴다
한 페이지 = 한 파일 규칙을 버리고 `css/`, `js/`로 쪼갰다. 테마 CSS/JS가 두 페이지에 복사돼 있다가 **이미 갈라진 상태**였기 때문이다 (`about.html`에 `--danger`가 없었고 테마 초기화 코드도 서로 달랐다). 이제 `css/theme.css`와 `js/theme.js`를 공유하므로 그 문제가 구조적으로 사라졌다.

- **ES 모듈은 쓰지 않는다.** `type="module"`은 `file://`에서 CORS로 막혀 더블클릭 실행이 깨진다. 평범한 `<script src>`를 의존 순서대로 둔다
- 각 파일은 전역 하나만 노출한다 (`Theme`/`Dates`/`Mood`/`Store`/`Calendar`/`Search`). `app.js`는 아무것도 노출하지 않음

### 저장 구조를 하나로 합쳤다
`todos`·`sortBy`·`notes` 세 키가 흩어져 있어 내보내기를 만들 수 없었다. 이제 `diary` 키 하나에 `{ version, days }`로 들어간다.

- **기존 데이터는 옮기지 않았다.** 마이그레이션 코드가 없다. 옛 키는 읽지 않지만 혹시 모르니 지우지도 않았다
- `id`를 `Date.now()`에서 `crypto.randomUUID().slice(0,8)`로 바꿨다. 가져오기로 여러 건이 한꺼번에 들어오면 밀리초가 겹쳐 엉뚱한 항목이 지워진다
- 깨진 저장값이 와도 `sanitize()`가 걸러내고 빈 상태로 시작한다
- **저장 실패를 더 이상 조용히 삼키지 않는다.** 저장 공간이 차면 화면 위에 빨간 띠가 뜬다. 일기는 다시 쓸 수 없는 글이라 모르고 지나가면 안 된다

### 마감일을 걷어냈다
날짜 중심이 되면서 `due`가 의미를 잃었다. 마감일 입력칸, 정렬 바(추가순/마감일순), `formatDue()`, `sortedTodos()`, 지남/오늘 마감 표시, `sortBy` 키가 전부 사라졌다.

⚠️ **"마감 3일 전부터 알림" 결정은 폐기됐다.** 할 일이 그날에 속하므로 마감일 자체가 없다.

### 새로 만든 것
- **날짜 계산** (`js/dates.js`) — 예전 코드엔 날짜 "계산"이 한 줄도 없었고 문자열 비교만 했다. 달력에는 월 그리드·윤년·월말 처리가 필수라 통째로 신규다
- **기분 5단계** — 한 번 눌러 기록이 남게 하는 게 목적. 글을 안 써도 된다. 기분이 있는 날은 달력 셀에 그 색이 옅게 깔린다. 같은 걸 다시 누르면 해제
- **어제 미완료 가져오기** — 자동으로 끌고 오지 않는다. 버튼을 눌러야 옮겨지고, 완료한 건 어제에 남는다
- **검색** — 일기 본문과 할 일 글자를 함께 훑는다. 강조는 `<mark>`를 쓰되 `innerHTML` 없이 문자열을 쪼개 붙인다
- **내보내기 / 가져오기** — JSON 파일. 가져오기 전에 현재 기록을 백업 파일로 먼저 내려받는다
- **연속 기록** — 오늘 아직 안 썼으면 어제부터 센다. 안 그러면 아침마다 0일이 된다
- **키보드 단축키** — `←→` 하루, `PgUp/PgDn` 한 달, `T` 오늘, `N` 기록 칸, `/` 검색, `1~5` 기분, `Esc` 빠져나오기

### 고친 문서 오류
`CLAUDE.md`가 코드와 어긋나 있던 것들을 바로잡았다.

- "Every mutation → save → render"가 **거짓**이었다. 정렬과 메모 두 군데가 이미 예외였다
- "두 페이지가 호환돼야 한다 / 새 색은 세 블록 모두에"가 **지켜지지 않고 있었다** (`about.html`에 `--danger` 없음)
- "페이지마다 같은 수정을 적용하라"도 **이미 어긋나 있었다** (테마 초기화 코드 상이)
- "가져오기를 넣으면 `id`를 바꾸라"는 자기 경고의 **발동 조건이 충족돼 있었다**
- `file://` 직접 열기가 ES 모듈과 **양립 불가**라는 사실이 어디에도 없었다
- 자정이 지나면 "오늘"이 틀어지는 한계가 문서에 없었다 → 이번에 `visibilitychange`로 고치고 기록했다

## 이번에 한 일 — 날짜 이동 버튼 + 예전 데이터 복구

### 어제 / 오늘 / 내일 버튼
상세 패널 제목 아래에 알약 버튼 세 개를 넣었다. 기존 `Dates.addDays()`와 `select()`를 그대로 쓰므로 새 계산 함수는 없다.

- `select()`가 달력도 다시 그리므로 **달이 바뀌면 달력이 따라 넘어간다** (10/31에서 `내일 ›` → 11월 달력)
- 오늘일 때 `오늘` 버튼은 **비활성**. 숨기면 옆 버튼이 밀려 자리가 흔들린다
- **달력 헤더의 `오늘` 버튼은 뺐다.** 같은 일을 하는 버튼이 두 군데 있으면 헷갈린다. 날짜 이동은 상세 패널 한 곳으로 모았고, 달력 헤더의 `‹ ›`는 달 이동만 맡는다
- 키보드 `←` `→` `T`는 그대로. 같은 `select()`를 거치므로 버튼과 결과가 늘 같다

### 예전 데이터 복구 (`Store.migrateLegacy()`)
재설계 때 "기존 데이터 버려"로 정했다가 다시 살리기로 했다. 옛 키를 지우지 않고 뒀던 덕에 가능했다.

- `notes[날짜]` → `days[날짜].note`, `todos[]` → 마감일이 있으면 그 날짜로, 없으면 오늘로
- **마감일은 되살리지 않는다.** 어느 날짜에 붙일지 정하는 근거로만 쓰고 필드로 저장하지 않는다 (할 일이 그날에 속하는 모델을 유지)
- **덮어쓰지 않는다** — 새 앱에서 이미 쓴 글이 있으면 건너뛰고, 할 일은 기존 목록 뒤에 붙인다
- `id`는 새로 매긴다. 옛 `id`는 `Date.now()`라 겹칠 수 있고 겹친 `id`는 엉뚱한 항목을 지운다
- 별도 키 `diaryMigratedV1`로 **한 번만** 돈다. 옮길 게 없어도 플래그는 세운다. `diary` 안이 아니라 별도 키인 이유는 가져오기로 `diary`를 바꿔도 마이그레이션이 되살아나면 안 되기 때문
- 깨진 값(배열 아닌 `todos`, `text` 없는 항목, `2026-13-45` 같은 날짜, 문자열 아닌 메모)은 **그 건만** 건너뛴다
- 옮긴 결과를 배너로 알린다 — 조용히 데이터가 늘면 혼란스럽다
- **옛 키는 그대로 남겨 뒀다.** 복구가 잘못돼도 되돌릴 수 있게

### 확인한 것
마이그레이션·날짜 버튼 40개 + 기존 회귀 54개, 합쳐서 94개 전부 통과.

## 확인 방법

빌드도 테스트 코드도 없다. 브라우저로 직접 열어 눌러 본다. (헤드리스 Chrome 스크립트로 54개 항목을 확인했고, 그 스크립트는 임시 폴더에만 두고 프로젝트에는 남기지 않았다.)

**가장 먼저 볼 것**
1. `index.html` **더블클릭** → 서버 없이 앱이 뜨는지. 안 뜨면 ES 모듈이 섞여 들어간 것이다
2. 기분·할 일·기록을 넣고 **새로고침** → 전부 남아 있는지

**달력**
3. `‹ ›`로 달 이동, 날짜 클릭 → 오른쪽이 그 날짜로 바뀌는지
4. 기분을 고른 날이 달력에서 색으로 보이는지. 같은 기분을 다시 누르면 해제되는지
5. 월 경계: 1일/말일, 12월에서 다음 달, 윤년 2028년 2월

**할 일**
6. 어제에 미완료를 남기고 오늘로 와서 `어제 미완료 N개 가져오기` → 미완료만 오고 완료한 건 어제에 남는지. 누른 뒤 버튼이 사라지는지

**검색**
7. 일기에 쓴 낱말로 검색 → 본문과 할 일 양쪽에서 찾고 강조되는지. 결과를 누르면 그 날짜로 가는지

**백업**
8. `내보내기` → JSON 파일이 받아지는지
9. 기록을 지우고 `가져오기`로 그 파일을 넣어 완전히 복원되는지
10. 아무 텍스트 파일이나 넣어보기 → 거부하고 **기존 기록이 그대로 남는지**

**날짜 이동 버튼**
11. `‹ 어제` / `내일 ›` → 하루씩 움직이고 달력 선택도 따라오는지
12. 10월 31일에서 `내일 ›` → 달력이 11월로 넘어가는지. 12월 31일에서는 다음 해 1월로
13. 오늘일 때 `오늘` 버튼이 흐리게(비활성) 보이는지
14. 버튼과 `←` `→` `T` 키의 결과가 같은지

**예전 데이터 복구**
15. 예전 할 일이 있었다면 앱을 처음 열 때 배너가 뜨고 날짜별로 들어왔는지
16. 새로고침해도 **중복되지 않는지**
17. 개발자 도구에서 `localStorage.todos`가 **아직 남아 있는지** (복구가 잘못됐을 때 되돌릴 수단)

**그 밖에**
18. 할 일이나 일기에 `<b>태그</b>` 입력 → 글자 그대로 보이는지
19. 기록 칸에 `t`나 숫자를 칠 때 단축키가 끼어들지 않는지
20. 라이트/다크 양쪽에서 기분 색 5개가 구분되는지, `about.html`과 테마가 연동되는지
21. 창을 좁혔을 때 위아래로 쌓이고 가로 스크롤이 없는지
